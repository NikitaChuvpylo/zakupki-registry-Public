# SPEC.md — Реестр малых закупок (заполнение ЕИС из PDF-контрактов)

## 1. Цель и ценность
- Одна главная задача: **PDF-контракт (скан с почты) → готовый Excel-файл по шаблону ЕИС «Объекты закупки», который пользователь загружает в ЕИС для повторного заполнения контракта на подписание.**
- Пользователь: специалист по закупкам (заказчик — МБОУ, 44-ФЗ, малые закупки).
- Критерий приёмки: пользователь загружает PDF контракта №7 (молоко) → система распознаёт реквизиты и спецификацию → выдаёт .xls по шаблону ЕИС с заполненными строками (наименование, код позиции ОКПД2, тип объекта 1, ед. изм. по ОКЕИ, количество, цена ед., НДС, страна 643, ГОСТ в пользовательских характеристиках) → файл открывается в Excel и принимается при импорте в ЕИС (проверка на 1 реальном контракте).
- Что НЕ входит в MVP: автопостинг в ЕИС с ЭЦП, синхронизация статусов из ЕИС, работа по 223-ФЗ, админка и права пользователей.

## 2. Стек (конкретный, минимальный)

## 6. Данные и модель
- Contract { id, num, date, customer, customer_inn, supplier, supplier_inn, ikz, total, vat_rate, status, source_pdf, created_at }
- Item (позиция спецификации) { id, contract_id, num, name, unit, qty, price, sum, okpd2, gost, extra_chars[], eis_row? }
- Excel-выгрузка = копия шаблона: строки с 7-й (после шапки 1–6), по строке на позицию.
- Внешние источники: PDF (загрузка файлом), шаблон ЕИС .xls. Почта Mail.ru — второй этап.

## Чек-лист задач (MVP, тонким срезом)
1. Загрузка PDF → рендер страниц → вручную-распознанное (через analyze_image в dev) → парсер реквизитов и спецификации №7 (полный срез данных в БД)
2. Генератор .xls из карточки: копия шаблона + строки позиций (ОКПД2, ОКЕИ, НДС, страна, ГОСТ в пользовательские характеристики) → проверка открытия в Excel
3. Веб-интерфейс: список контрактов, карточка с редактированием распознанного, кнопка «Скачать для ЕИС»
4. Почта Mail.ru (IMAP): «Забрать письма» → PDF в реестр (нужен пароль приложения)
5. Полировка: статусы контрактов, поиск, проверка на 2–3 реальных PDF
