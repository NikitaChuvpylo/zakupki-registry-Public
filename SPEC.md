### Технические решения
- **Порт 3001** (3000 занят старым сервером кофейни coffee-time — не трогаем).
- **БД:** встроенный `node:sqlite` (не нужен better-sqlite3). Файл `data/registry.db`.
- **PDF → PNG:** mupdf (wasm). Страницы: `data/contracts/<id>/pages/`, отдаются на
  `/files/<id>/pages/`.
- run() в node:sqlite возвращает `lastInsertRowid`, не `id` — учтено.

### Авторазбор — статус
- OCR: tesseract.js (rus), рендер страниц scale 3.5 (~250dpi), PSM 6 (таблицы), TSV-координаты → восстановление строк.
- Сортировка страниц: заголовок «Приложение №1/СПЕЦИФИКАЦИЯ» → первой, затем по печатному номеру листа вверху (если есть), без номера — в конец. Это чинит перемешанные страницы в PDF.
- Позиции нумеруются по физическому порядку отсортированных страниц (не по номеру из PDF — OCR его теряет), номера из PDF — «якоря» для интерполяции.
- Проверено на контракте «оп5246» (65 позиций, PDF с перемешанными страницами): порядок теперь верный (Сыры→Мясо→Рыба→…), распознано 46/65. Пропуски — предел локального OCR (числа слипаются). Добивка — vision-моделью в чате или вручную.
- Тёмная тема — сделана. Строка ИТОГО под таблицей — сделана.
- ВАЖНО про \b в JS: кириллица не считается \w, поэтому \b перед кириллицей не работает — использовать (^|\s).

### Публикация (инструкция пользователю — в чате)
1. Создать GitHub-репозиторий, залить файлы проекта (без node_modules).
2. Render → New → Blueprint → выбрать репозиторий (render.yaml найдётся сам).
3. Через ~3 мин получить https://zakupki-registry.onrender.com
4. Открыть с телефона/другого ПК, загрузить PDF → скачать Excel.
